## Реализованное состояние

- Команды сборки, проверки типов и Vitest; ESM/NodeNext с decorator metadata. `start:dev` использует tsc-watch и запускает скомпилированный JavaScript.
- Отдельные Nest-контексты основного процесса и CLI. Настройки Discord, SQLite и health передаются через узкие неизменяемые Config. Ошибки конфигурации содержат имя настройки без значения. CLI восстановления через nest-commander открывает DataSource без миграций и выполняет OwnerRecoverCommand без Discord-модулей и token. Предварительной проверки схемы нет; команда обрабатывает ошибку самой операции БД.
- Конфигурация приведена к примеру GoldGiverBackend: env-группы в `src/config/env`, общая валидация class-transformer/class-validator, модульные Config с private readonly полями и getters, injectable ConfigFactory, FactoryInterface и CreateConfigProvider. Options TypeORM собирает DatabaseOptionsFactory через useClass и extraProviders.
- JSON-логгер и адаптер логирования TypeORM без SQL, параметров и сырых сторонних ошибок.
- Очередь по ключу и отдельный исполнитель коротких операций одного соединения SQLite. Повторный захват своей очереди завершается ошибкой вместо взаимного ожидания.
- Семь моделей у владельцев данных и две сгенерированные TypeORM миграции, включая отметку незавершённой очистки guild. Включены WAL и ожидание блокировки 1000 мс, `synchronize` и `migrationsRun` выключены. Runtime, migration CLI и операторский CLI используют общий состав моделей и options; применение и откат выполняются только отдельными явными командами TypeORM CLI.
- Repository временных каналов: сохранение, чтение, подсчёт всех отслеживаемых каналов, условное резервирование попытки удаления и идемпотентное удаление записи. Попытка резервируется отдельной завершённой операцией до будущего Discord DELETE.
- Добавлены Repository и Service триггеров и лимитов, Handler регистрации, снятия наблюдения, изменения лимита, AFK и удаления триггера. DiscordVoiceChannelAdapter реализует VoiceChannelGatewayInterface; Observer и девять подкоманд подключены к Necord. Сеть в проверках подменяется.
- OwnershipRepository скрывает атомарное хранение владельца, кода и попыток; OwnerCodeService генерирует и сравнивает коды, OwnershipService реализует initialize, claim, transfer, recover и assertOwner. Начальный код выводится до login только без владельца; восстановительный код попадает только в stdout CLI после commit.

## Триггеры, лимиты и жизненный цикл временного канала

На этапе до подключения Discord-адаптера `npm test` выполнял **52 теста в пяти файлах**. Тесты бизнес-сценариев использовали настоящую SQLite с миграцией и подменяли Discord-операции; чистые правила cooldown и идентичности входов проверялись без БД. Ранее написанные пять тестов бюджета удаления сохранены. Проверены:

- отказ для Stage, неподходящего типа, AFK, уже управляемого временного канала и недостаточных permissions из gateway-контракта;
- повторный watch без записи в SQLite и без переноса границы новых входов;
- индивидуальный лимит до watch, сохранение при unwatch/rewatch, снятие наблюдения при AFK, очистка только неактивной конфигурации без лимита и связанных каналов;
- удаление настройки физически удалённого триггера без удаления его временных каналов; проблемные каналы и каналы без триггера остаются в лимитах;
- одновременные входы в разные триггеры не обходят общий лимит; несколько входов в один триггер не обходят индивидуальный;
- значение 0 снимает ограничение, снижение лимита не удаляет существующие каналы и не создаёт новые до освобождения слотов;
- cooldown 5 секунд устанавливается после успешного перемещения, действует по guild/user, не затрагивает других пользователей и не возникает после отказа создания, ошибки перемещения или отката;
- приём перехода до очереди, граница успешного watch, исключение уже присутствующих пользователей и событий, полученных во время watch; одинаковый channel ID и боты не создают вход;
- выход и возврат в тот же триггер делают старый вход недействительным; повторная доставка обработанного входа не создаёт канал даже после истечения cooldown;
- ID канала сохраняется до перемещения; устаревший вход после Discord create вызывает общий откат, занятый канал сохраняется;
- попытка удаления фиксируется до внешнего DELETE, расходуется не более трёх попыток, немедленного retry-цикла нет; подтверждённое отсутствие очищает запись при любом бюджете;
- неизвестный состав и занятость не запускают удаление. После резервирования пустота проверяется повторно: если за время записи вошёл человек, DELETE не выполняется, но зарезервированная попытка остаётся потраченной;
- конкурентные запросы удаления и пересечение с откатом получают результат одной попытки; тест сначала воспроизвёл расход двух попыток, затем прошёл после исправления;
- отказ сохранения после Discord create не объявляется успехом: выполняется безопасная компенсация известного ID, ID остаётся в безопасном логе; необратимый отказ закрывает допуск новых и ожидающих guild-операций, временная SQLite busy не закрывает допуск;
- ожидание Discord в одном guild не блокирует другой guild и не удерживает очередь SQLite.

Отдельная локальная smoke-проверка собранного JavaScript создала настоящий Nest application context с `VoiceModule.withGateway` и подменённым модулем внешних операций. Через публичные Handler выполнены watch, установка лимита, создание, сохранение ID, перемещение, сохранение занятого канала и удаление после опустения. SQLite настоящая; после `app.close()` DataSource закрыт. Это проверка сборки и DI с подменой Discord, без login, Gateway или HTTP.

Repository остаются внутри своих функциональных модулей. Service/Handler получают DTO и числа, не ORM Entity/Repository. Новые env-параметры и зависимости на этом этапе не добавлялись.

## Discord Gateway, сверка и завершение операций

Результат этапа на 2026-11-13: **72 теста в восьми файлах**. Новые тесты защищают собственные правила копирования канала, классификации состава и доступности, сверки и завершения операций. Настоящие SDK-объекты используются для enum, permissions и коллекций; внешние вызовы подменены.

- Один POST передаёт совместимые голосовые настройки, изменяемый флаг и permission overwrites, без позиции. Существующий overwrite создателя объединяется без дубликата; добавляются только ViewChannel, Connect и ManageChannels, соответствующие Deny снимаются, остальные права сохраняются. Unicode-имя не обрывает суррогатную пару. Невоспроизводимые overwrites отклоняются до POST.
- Пустота определяется по обычным пользователям, боты не учитываются. Неизвестный участник, потеря ViewChannel, обфускация и ошибка доступа оставляют состояние Unknown. UnknownChannel становится Missing только в прежнем доступном поколении. Голосовые состояния перечитываются после ожидающих обращений.
- Начальная сверка не создаёт комнаты для уже присутствующих пользователей. Новые входы сохраняются до окончания сверки; ушедший пользователь не получает комнату. Выход из уже проверенного канала во время сверки не теряется. Предыдущие поколения входов после reconnect недействительны.
- Занятые и недоступные временные каналы остаются в SQLite и лимитах; подтверждённо отсутствующие очищаются. AFK теряет регистрацию, сохраняя индивидуальный лимит; физически удалённый триггер теряет настройку, сохраняя связанные временные каналы.
- Подтверждённый channelDelete идемпотентен. Прерванная очистка guild сохраняет отметку и продолжается после повторного открытия настоящей SQLite; повторное приглашение guild также сначала завершает старую очистку. Временная недоступность не очищает данные.
- Необратимый отказ записи созданного ID компенсирует известный канал и уведомляет основной процесс о завершении. Shutdown отклоняет ожидающие и новые операции, ждёт выполняющуюся; превышение 15 секунд завершается ошибкой. Срок проверен с управляемыми часами Vitest.

Сквозная ручная проверка скомпилированного приложения использовала настоящий Nest application context, Necord listeners и SQLite, с подменой login и сетевых операций. До импорта приложения заданы фиктивный token и временные пути. Любой неожиданный REST request отклонялся. Подтверждено:

1. БД с первой миграцией и существующими каналами обновилась до двух миграций без потери данных до вызова Client.login; listeners уже зарегистрированы.
2. ClientReady запустил сверку без создания комнаты; VoiceStateUpdate прошёл через декоратор Necord до создания, сохранения ID и перемещения. Последующий выход удалил пустой канал; занятый сохранился.
3. GuildUnavailable сохранил SQLite, GuildAvailable выполнил сверку, GuildDelete запустил подтверждённую очистку.
4. Синтетическое уведомление channelDelete внутри REST-операции поставлено отдельной операцией. Обнаруженная при первой проверке ошибка наследования контекста очереди исправлена и защищена регрессионным тестом.
5. При app.close текущая операция удерживалась проверочным барьером: Client.destroy ещё не вызывался, DataSource оставался открытым. После снятия барьера завершились операция и закрытие обоих ресурсов.

После изменений выполнены `npm.cmd run lint`, `npm.cmd run format:check`, `npm.cmd run typecheck`, `npm.cmd test`, `npm.cmd run build` и проверка diff. Сверка схемы TypeORM не обнаружила расхождений моделей и миграций.

Это локальная проверка интеграции, а не проверка настоящего Gateway/API. Копирование полей и минимальные разрешения на тестовом guild, настоящий сетевой reconnect, команды, health/CLI health, Docker и серверная приёмка остаются впереди. Новые env-переменные на этом этапе не добавлялись.

## Ownership и CLI recovery — 2026-11-16

Перед изменениями прошли исходные 72 теста. Добавлены 14 бизнес-сценариев в [OwnershipService.spec.ts](../../../src/modules/Ownership/Service/OwnershipService.spec.ts); все используют настоящую временную SQLite, подменяются только часы и отдельные точки конкурентного исполнения. Тесты не требуют Discord, Nest-контекста или предварительной сборки.

- Начальный код состоит из 32 букв и цифр, в хранилище остаётся только SHA-256; повторная инициализация без владельца заменяет код, назначенный владелец предотвращает генерацию. Повторный claim уже погашенного кода не меняет владельца.
- Transfer сохраняет текущего владельца до успешного claim, заменяет предыдущий код и истекает ровно через 24 часа. Дополнительно проверен код, истёкший между проверкой и записью: владелец не меняется, попытка не расходуется.
- Пятая неверная попытка блокирует пользователя на 15 минут; блокировка сохраняется после повторного открытия SQLite. Во время блокировки хеш не проверяется; после срока доступны новые пять попыток. Успех сбрасывает только состояние заявителя.
- Recovery аннулирует владельца и предыдущие коды; восстановительный код не имеет срока действия до использования или замены. Авторизация после очереди читает нового владельца, уже допущенная операция может закончиться после recovery.
- Устаревший снимок, SQLite busy и конфликт не расходуют попытки. Искусственный отказ удаления кода откатывает назначение владельца и сброс попыток; отказ обновления кода при recovery откатывает отзыв владельца. Отдельные подключения допускают только одного успешного claimant.

Отдельная ручная проверка собранного JavaScript запускала независимые Node-процессы с собственными DataSource и настоящими OwnershipService/Repository. Процессы останавливались барьером после чтения одного и того же состояния, затем одновременно продолжали запись. Источником определений служит discovery установленного Necord 7.1.1; особенности сравнения проверены по исходникам установленного discord.js 14.28.1 и с его настоящими объектами ApplicationCommand.

Реализованы три подкоманды /voice (watch, unwatch, list) и шесть /owner (claim, transfer, watch, unwatch, list, limit). Voice зарегистрирован для Guild с ManageGuild; owner — для BotDM, оба с GuildInstall. Английские описания и ответы имеют RU-локализацию; для остальных locale применяется английский.

На Windows x64 / Node.js 24.22.1 / npm 11.19.1 выполнены:

- `npm.cmd test`: 124 теста в двенадцати файлах. Новые сценарии проверяют отзыв владения во время ожидания watch/unwatch/limit/list, право завершить уже допущенную операцию, статистику активных/неактивных/отсутствующих триггеров, общий лимит и комнаты с исчерпанными попытками.
- Сценарии представления проверяют RU/EN, отсутствие данных владельца в guild-списке, размер страниц до 2000 символов, упоминания проблемных комнат, автора кнопок, текущие права, исходный срок 15 минут без продления и недействительность старых кнопок после потери памяти процесса.
- Autocomplete проверяет владельца, фильтрует по имени/ID и ограничивает выдачу 25 вариантами. Проверены пустой ответ постороннему, чужие guild/channel, неподходящий тип канала и пустой результат при превышении бюджета 2 секунды. Ручные ID проверяются независимо от подсказок; изменяющие Handler заново проверяют доступность guild после очереди.
- Синхронизация не пишет эквивалентные определения, игнорирует ID/version и различия отсутствующих default-полей. Изменение description, RU-локализации корня или параметра, contexts и permissions вызывает одно адресное обновление; отсутствующая команда создаётся отдельно. Второго набора описаний нет.
- Отдельный прогон скомпилированного AppModule создал настоящий Nest-контекст, discovery и listeners Necord, временную SQLite и объекты discord.js. Login, REST и получение фактов канала были подменены; сетевой доступ был запрещён. Все девять подкоманд прошли через interactionCreate: claim реально назначил владельца, transfer вернул код, watch/unwatch/limit изменили SQLite, list сформировал страницы. Проверены порядок параметров, RU-описания, классы options DTO, обычные DM и ephemeral guild-ответы, локализованные безопасные отказы.
- Настоящий ButtonInteraction прошёл через динамический matcher Necord и ComponentParam: автор получил вторую страницу, посторонний и потерявший владение автор получили отказ. С настоящими ApplicationCommand проверены две начальные create, повтор без записи, одно обновление устаревшей RU-локализации и повтор без записи.
- Интеграционная проверка выявила попытку class-transformer глубоко пересоздать VoiceChannel. CommandOptionsPipe исправлен: создаёт экземпляр options DTO и копирует только его поля, сохраняя ссылку на SDK-канал. Регрессионный сценарий защищает это поведение.
- `npm.cmd run check`: автоисправления/проверка стиля, typecheck и build прошли. `git diff --check` прошёл. Схема и миграции этим этапом не изменялись.

Ограничения: локальные моки не подтверждают HTTP-запись определений в Discord, отображение команд в настоящем DM/guild, применение permissions настоящим приложением и сетевой reconnect. Поэтому T060 остаётся открытой, а эти проверки сохраняются также в T040/T084. Следующая реализация — health-файл и CLI health (остаток T072), затем Docker и CI/CD.

## Упрощение авторизации и очередей — T065, 2026-11-17

По уточнению пользователя проверка владельца выполняется один раз при принятии команды, до ожидания очереди guild. Принятая команда может закончиться после смены владельца; новая команда, Autocomplete и каждое нажатие кнопки проверяют актуальные права. Voice-handler не принимает ID глобального владельца и не зависит от Ownership.

Чтение списков, общий лимит guild и пагинация не используют очередь guild. Создание комнат, watch/unwatch и индивидуальные лимиты триггеров сохраняют сериализацию. Сессия пагинации хранит готовые страницы, автора и исходный срок действия; каждая кнопка задаёт целевую страницу без изменяемого счётчика.

Проверены собственные правила:

- Настоящие OwnerCommandController, Voice-handler и OwnershipService с временной SQLite: watch/unwatch/limit/list принимаются владельцем при занятой очереди guild; recovery и назначение нового владельца не отменяют принятую команду. Повторной авторизации внутри команды нет, следующая команда прежнего владельца отклоняется.
- Пока watch ожидает подменённый Discord, общий лимит того же guild меняется и список читается без ожидания; индивидуальный лимит применяется после watch с сохранением конфигурации триггера.
- Два одновременных нажатия одной кнопки показывают одинаковую целевую страницу. Полный обход списка использует кнопки из каждого нового ответа. Проверены недопустимые номера страниц; сохранены проверки автора, актуальных прав, RU/EN, размера ответа, истечения исходных 15 минут и потери сессии после перезапуска.

Среда: Windows x64, Node.js 24.22.1, npm 11.19.1. Выполнены npm.cmd test — **127 тестов в двенадцати файлах**, npm.cmd run check — автоисправление и проверка ESLint/Prettier, typecheck и build; проверка diff и локальных ссылок документов. Проверки SQLite используют настоящую временную БД; Discord-вход и ответы подменены. Настоящий Discord, Docker и развёрнутое приложение не проверялись. T065 завершена; следующий этап реализации — остаток T072.
