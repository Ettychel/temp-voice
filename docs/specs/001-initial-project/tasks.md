Основания: [spec.md](spec.md), [plan.md](plan.md), [research.md](research.md). Отмеченные задачи относятся только к фактически выполненной работе. Проверки реального Discord и deployment требуют соответствующей среды.

## Текущее состояние и следующий шаг

Сверено с исходниками 2026-11-15, базовая реализация — коммит `bc7590d` в `feature/first-release`. **Следующая задача — T050, следующий этап — T050–T053 (Ownership и CLI recovery)**. Точка продолжения и состав готовых компонентов находятся в [plan.md](plan.md#точка-продолжения--2026-11-15).

`[x]` означает выполнение проверки, описанной у задачи; локальная проверка с подменой сети не подтверждает настоящий Discord. Незавершённые задачи с готовой частью оставлены открытыми, а точный остаток указан у соответствующего пункта. Последняя полная проверка кода — 2026-11-13: 72 теста в восьми файлах, lint, format:check, typecheck и build; подробности — в [verification.md](verification.md).

## Жизненный цикл каналов

- [ ] T040 Реализовать Discord-адаптеры, создание GuildVoice и применение настроек и overwrite создателя. Проверка: критерии 3–5 и 7–8; имя и позиция следуют spec, дополнительные права управления участниками не выдаются; фактические permissions и поля проверяются на тестовом guild. Адаптер и копирование одним POST реализованы, собственные правила проверены с подменой сети. Осталась приёмка полей и минимальных прав в настоящем Discord.
- [x] T041 Реализовать очередь создания, сохранение ID, повторную проверку входа и перемещение. Проверка: одновременные события, смена канала, выход и возврат в тот же триггер не создают канал по устаревшему входу; cooldown возникает только после успеха. Проверено с подменой Discord; повторная доставка входа не создаёт новый канал даже после cooldown.
- [x] T042 Реализовать общий сценарий удаления: пустота по обычным пользователям, резервирование попытки до REST, максимум три попытки, отсутствие немедленного retry-цикла. Проверка: критерии 9–10 и 17–18; незавершённая при аварии попытка сохраняется, проблемный канал остаётся в лимитах. Конкурирующие запросы и пересечение с откатом используют одну попытку. Классификация состава, неизвестного участника и отказа доступа проверена также через DiscordVoiceChannelAdapter с подменой сети; реальная приёмка Discord остаётся в T040.
- [x] T043 Реализовать откат при уходе создателя и ошибке перемещения. Проверка: критерий 16; занятый другим человеком канал сохраняется до опустения, cooldown не ставится, неудачное удаление сохраняет запись и бюджет; ошибка SQLite не объявляется успехом. Сценарии и компенсация несохранённого ID проверены с настоящей SQLite и подменой Discord; необратимый отказ БД закрывает допуск и уведомляет основной процесс о завершении. Health-файл остаётся отдельным остатком T072.
- [x] T044 Реализовать channelDelete и очистку данных после подтверждённого удаления бота из guild через операции владельцев данных. Проверка: повторы идемпотентны; временная недоступность guild не очищает БД; незавершённая очистка продолжается по сохранённой отметке после перезапуска или перед принятием повторно приглашённого guild. Проверено на настоящей SQLite с подменой сети, включая доставку событий настоящими listeners Necord.

## Порядок выполнения

Текущий порядок продолжения: **T050 → T051 → T052 → T053 → T060–T064 → остаток T072 → T080–T084**. T013 и T022 завершить после проверки Ownership/T052. T070–T071 уже реализованы и локально проверены; повторно создавать сверку и обработку reconnect не требуется. T040 остаётся открытой до приёмки на настоящем тестовом guild; сетевые проверки T071 и остальных Discord-сценариев входят также в итоговую приёмку T084.

Для T050–T053 использовать существующие модели Ownership и общий исполнитель БД; добавить бизнес-операции и их атомарное хранение, а затем подключить отдельный CLI без Discord Client и автоматического запуска миграций. Проверки реального Discord выполняются при наличии тестового guild; непроверенные результаты не отмечаются выполненными.

После каждого этапа выполняются релевантные бизнес-тесты, lint, typecheck и build. Тесты проверяют собственные правила, а не повторяют тестирование SDK, ORM, конфигурации и регистрации providers.
